# Bearly Chat

A simple check-in for toddlers to pick a feeling and a color that matches how they feel.

Serve the app over HTTPS or localhost to use location and save check-ins. To install it on a device, publish all app files (including the `icons` folder) together on an HTTPS web host. Installation and offline support also require HTTPS, or localhost for development. No account is required.

After choosing a feeling, a popup shows and speaks its name when a device voice is available. Choose **Yes** to continue to colors or **No** to choose another feeling. Choosing a color likewise opens a popup that shows and speaks its name; choose **Yes** to continue or **No** to choose another color. After a feeling and color are selected, the device owner can optionally add notes, then an adult can allow the browser to access the device's location. On the notes page, press Enter to continue to the save confirmation or Shift+Enter to add a new line. Location is required to save; if permission is denied or location is unavailable, the check-in is not saved. Each saved check-in contains the feeling, color, notes, local date and time, UTC timestamp, UTC-minus-local offset in minutes, coordinates, reported location accuracy, and the browser-provided device/browser description (not a unique device ID). Older check-ins have no device description or notes. Records are stored in a local browser database and are not sent by the app to a server. Browser storage can be cleared or unavailable, and records do not sync between browsers or devices. Location may use GPS, Wi-Fi, or other device services; offline saving works only when the device can determine its location without a connection.

After saving, the final popup offers **Save and Download Check-In**, which downloads the complete current check-in as `check-in.csv`, including location, device details, and an approximate location link, or **Close**, which keeps it on the device. The link contains the recorded coordinates, which may be precise even though the location is approximate; opening it shares those coordinates with Google Maps. No place name or city is looked up, and the link is blank if coordinates are unavailable. Creating the CSV works offline and does not require an API key. Check-ins waiting to be downloaded remain queued across app updates and are listed under **Saved check-ins**. After a download starts or a folder export completes, verify the file was saved: browser downloads can fail or be cancelled after starting. Choose **File saved - clear downloaded data** to remove only the exported records, **File saved - keep data** to keep them while marking them downloaded, or **Not sure - keep data** to leave them queued. Dismissing the popup also keeps the records. There is no separate delete-all action; to clear previously kept records, export them again and choose to clear them. Select **Saved check-ins** to review or export records. **Export checkins.csv** asks you to choose a parent folder in browsers that support folder access; it creates a `checkins` folder there and creates or replaces `checkins.csv` with all current records, including notes, location, and device data. In other browsers, the file downloads as `checkins.csv` to the browser's download location; create a `checkins` folder and move it there if desired. Exports are snapshots and are not updated automatically. Exports may contain sensitive information: keep them private and delete exported copies separately. Browser or device storage can still be cleared or evicted outside the app's control.

The installed app offers a demo on its first launch, when the browser can detect that it is installed. You can also select **Help** at the top of the page and **Start demo** at any time for a step-by-step walkthrough that does not save a check-in or request location. Help and the demo link to the app's website for installation troubleshooting. Choose **Print or save as PDF** in Help or the demo to print all the walkthrough steps and the website link, or select **Save as PDF** in the device's print options, where available. The demo leaves an unfinished check-in unchanged and is available offline after the app has been cached. Clearing browser storage can cause the first-launch offer to appear again.

An install popup appears once per browser-tab session, or select **Install app** in the header at any time. Installation does not request or depend on location; location is requested later when saving a check-in. Supported browsers show their install prompt; otherwise the app shows instructions for your device. On iPhone and iPad, tap Share and choose **Add to Home Screen**; if that option is missing, use Safari. On a Mac, Safari offers **File > Add to Dock**. Chrome and Edge also offer installation from their menus or address bars. The browser and operating system control installation, and availability varies by device. Device location services may need to be enabled in settings; the app cannot turn them on automatically. Installed apps may have separate location permissions and storage from the browser, so existing check-ins might not appear in the installed app.

Open the app online once and allow the offline cache to finish installing before using it offline. The header shows the browser's reported online or offline status, which does not guarantee internet access. Offline check-ins still require a device location fix; device-provided speech voices and downloaded fonts may not be available offline. Google Maps links require a connection to open.

The first screen offers **Voice preference** with female and male options and **Hear voice** to preview or retry the selection. The preference is saved in this browser, and the same selected device voice is used for questions, choices, and thank-you messages until the preference is changed or previewed again. The app identifies available English voices by their device-provided names, which may not accurately indicate voice gender; if no matching voice is found, the app reports the fallback. Voices vary by device and may load later, require a download or internet connection, or be unavailable. Some browsers, including Safari on iOS, require a tap before speech can play: use **Hear the question** on the first screen. The color question is spoken after confirming a feeling. The sound button can repeat either question.

When the installed app opens, it checks for updates before starting a check-in. If an update is ready, it installs and reloads automatically; saved check-ins remain on the device. If the check fails or takes too long, the app offers **Continue without updating**. A later update or an update in a browser tab shows an **Update app** notice instead, so an unfinished check-in is not interrupted. Existing installations running an older version may need to select **Update app** once to receive this startup behavior. Updates require a connection and service-worker support. Bump the cache version in `service-worker.js` whenever publishing app-file changes so the browser detects a new worker and refreshes the offline cache. The browser and operating system control installed app names and icons; changes may be delayed or require user approval even after the app updates. For icon changes, publish icons under new filenames and update the manifest paths so browsers can detect them.
